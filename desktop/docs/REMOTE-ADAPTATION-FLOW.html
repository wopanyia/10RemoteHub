新遥控器接入流程

10RemoteHub 0.3.x 统一版：从插上接收器或连好蓝牙，到按键执行动作、语音出字。左边是一步一步的操作，右边是这一步软件能做到和做不到的事。

用户拿实物、点按钮 软件自动完成 AI / 开发者写适配器 ✓能做到 !限制或待实机验证 ✕做不到

先分清两样东西

  • 遥控器是手里那只：照片、键位、配置方案、语音设置都记在它身上。
  • 接收端是电脑真正看到的 USB 接收器或蓝牙设备。
  • 一只遥控器可以接受多种接收端；同一种接收器插哪一个都能用。
  • 一个接收端也能被几只遥控器共用，按当前启用的那只理解按键。电脑看不出是哪只遥控器按的，只看得到键码。

一步一步到能用

1

连接

用户

插上 USB 接收器，或在系统设置里配对蓝牙遥控器。

通过：系统设备列表里能看到，连接不反复断开

系统都看不到 → 软件无法处理，记为限制

边界
✕软件不负责配对，也修不了连接不稳。
!系统已配对不等于 App 能读到按键（BLE 遥控器 FIBER0D 在 Windows 上就是这样，要改用外接 USB 蓝牙棒直连）。
2

添加，App 找到它

用户软件

「我的遥控器」→「添加遥控器」。软件先暂停当前映射，再列出可读的 USB／蓝牙按键设备。

通过：列表里出现这只设备

系统已连但列表没有 → 点「没检测到我的接收器 / 蓝牙设备？」选出它，App 判断边界类型，再点「复制给 AI 的求助」

边界
✓标准键盘页、媒体键页的 HID 接口（Mac IOHID、Windows Raw Input）。
✕手柄按钮页、厂商私有页、电源/睡眠键页、私有 USB 接口、只有 GATT 的蓝牙。读不了的设备会列出来并判断类型，旁边可复制给 AI 的求助（含以往做法和可尝试方向，见 SKILL.md 6.5）。
!Mac 需要输入监控权限。Linux 暂无这条读取路径。
3

试按一颗键

用户软件

选中设备，点「开始检测」，按一颗数字键或方向键再松开。只监听所选设备。

通过：收到唯一一对按下和松开，显示键码

只有按下 / 多个信号 / 无信号 → 换键重试，仍不行就复制诊断

边界
✓主键盘按同名键不会被当成遥控器。
✕两颗实体键发出完全相同的报告时，只能当作同一个键。
!添加窗口试按时不拦截原键；保存后日常使用会自动按设备屏蔽已学原键（Windows 普通权限不拦截管理员前台窗口）。
?

识别协议，再照片学键

软件

按连接（厂商/产品编号、蓝牙 GATT 服务）识别按键协议和语音协议，不按外观猜型号：同一协议的遥控器键数和外观可以完全不同。

有麦克风：先标语音键

导入正面照片后先在照片上点一下语音键。命中内置语音协议（0416:0602、FIBER0D、ATV Voice）不用按语音键，保存后可用遥控器麦克风；未命中时按一下语音键记下键码，用来触发识别。

再逐个学按键

点一个位置、选分区和键位（或直接按标准 HID 键自动识别），按一下对应实体键，逐个学，起名后保存。点错的位置随时可删。

边界
!软件不内置按外观区分的型号预设：用户自己的照片无从知道哪个是「1」，所以每个键都由用户点位置并按实体键确认。
✓任何能读到稳定、可区分键码的设备都能手学。
4

保存并开始读取

软件

新建这只遥控器，默认接受“同一种接收端的任意一个”，切换为当前遥控器，恢复读取。接收端已被别的遥控器用了会提示。

通过：侧栏显示「已连接」

边界
✓换一个同类接收器不用重新添加。配套接收器 0416:0602 走专用采集，系统蓝牙读不了的 BLE 遥控器走外接蓝牙棒直连，其他走共享 HID。
!同一时间只启用一只遥控器；两个接收器同时插着只读其中一个，拔掉才换另一个。
✕共用接收器时分不清是哪只遥控器按的。
5

系统准备

用户

保存后弹出「还差几步」清单，只列这只遥控器需要的（必须 / 可选），侧栏「完成设置」可随时再打开：

配套接收器 0416:0602

Mac：读取组件 + 辅助功能。Windows：在添加窗口一键让 App 接管（系统自带 WinUSB，接管 Interface 4 完整按键、Interface 3 收音），Zadig 仅作备选。

其他 USB／蓝牙

Mac：输入监控 + 辅助功能。Windows：不需要额外准备。

系统蓝牙读不了的 BLE 遥控器

Windows：插外接 USB 蓝牙棒，在添加窗口一键切换直连，选中遥控器后扫描。macOS / Linux：待验证。

边界
✕软件不替用户输密码、不关系统保护、不随包分发 VB-CABLE；接管接收器和切换蓝牙棒都要用户在管理员确认框里点「是」。
6

分配动作并试用

用户

在照片上点键，选动作（快捷键、打开 App、文本、九宫格输入等），再按实体键。

通过：用户亲眼看到动作完成

边界
✓每只遥控器有自己的配置方案和按应用切换的按键层。
!App 发出按键不等于目标软件收到：Windows 管理员窗口、豆包输入法会拦。
?

语音：声音从哪来？

用户软件
命中内置语音协议（0416:0602 / FIBER0D / ATV Voice）

可选遥控器麦克风：专用采集或蓝牙棒直连 → 本机解码 → 虚拟麦克风 → 识别软件。

其他遥控器

语音页引导：识别软件里选好麦克风 → 一颗键触发识别快捷键 → 说一句 → 用户点「确认已听写成功」。

通过：识别软件写出文字，由用户确认

边界
✓系统本来就能选到的遥控器麦克风，可以直接在识别软件里用。
!软件只能确认“快捷键已发出”，识别软件是否接受要人看。
✕其他遥控器的私有音频协议不能直接用，需要写适配器。
7

日常维护

用户

侧栏「学习更多按键」补键（自动同步到所有配置方案），从新类型接收端学键时自动接受该类型；在侧栏或「我的遥控器」里切换、重命名、删除。

边界
✓每只遥控器的语音设置分开保存，切换不互相覆盖。

卡住了怎么办

任何一步没通过，都走这条路。按 SKILL.md 第 6 节把记录表发给维护者。

复制接入诊断

只含系统、连接方式、型号编号、卡在哪一步；不含序列号、按键内容和音频。

→

填接入记录表

s0 到 s7 每步填亲眼看到的结果，标出第一处卡住的地方。

→

样机试验 AI / 开发者

授权后对目标设备做最小采集：比报文、找区别、推断重组和编码，写回放测试。

直接照片学键

标准 HID 能稳定读键：不用写代码，用户导入照片学键即可。

写适配器

系统不暴露按键或要私有音频：按读取端约定实现，再按“控制 → 报文 → 重组 → 解码 → 送入识别软件 → 重连”逐段验收。

记为限制

没有可区分的信号，或系统根本不暴露接口：写进限制说明，不改代码。

下一步要扩的边界

  • 读取端同时打开多个接收器（现在一次一个）。
  • 蓝牙棒直连在 macOS / Linux 上实机验证（Linux 还需为蓝牙棒加 udev 权限）。
  • 支持手柄按钮页、电源/睡眠键页。
  • Linux 的共享 HID 读取（Linux 代码保留在主干，暂不分发安装包）。
